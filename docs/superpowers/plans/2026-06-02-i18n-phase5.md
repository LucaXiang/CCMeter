# Phase 5 — Internationalization (EN ↔ ZH) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`).

**Goal:** All user-visible UI text switchable between English and 中文. Default language auto-detected from `$LANG`/`$LC_ALL`/`$CCMETER_LANG`; overridable + persisted via a /settings toggle.

**Architecture:** A tiny `src/ui/i18n.rs` holds a process-global current language (an `AtomicU8`) and a translation function `t(&'static str) -> &'static str`. `t(en)` returns the input verbatim under English; under Chinese it matches the English literal to a Chinese literal (giant `match`), falling back to the English input when no arm matches (graceful — a missed string just stays English, never breaks). Every user-visible literal in `src/ui/**` (and the `"All"` source tab in `app.rs`) is wrapped `t("…")`; format-composed strings wrap only their literal part: `format!("in: {}", x)` → `format!("{}{}", t("in: "), x)`. The global is set once at startup (from persisted Settings, else `detect()`), and on the settings toggle.

**Why a `&'static str` match (not a HashMap):** all UI literals are already `'static`; the match arms return `'static` Chinese literals; no allocation, no leak, O(log n) after the compiler's match optimization, and the fallback arm `_ => en` guarantees safety. No `lang` parameter has to be threaded through render functions (they read the global), so the apply step is a pure literal-wrap with near-zero signature churn.

**Source of truth:** the ~135-string catalog (7 groups) produced for this phase. The catalog records each English literal **with its exact surrounding spaces** — arms and call-sites must use the literal verbatim so they match.

**Tech Stack:** Rust 2021, ratatui. Build/test: `cargo +1.95.0` (binary crate, no `--lib`).

- [ ] **Step 1 (RED):** unit tests:

  - `#[derive(Clone,Copy,PartialEq)] pub enum Lang { En, Zh }`.

  - `pub fn from_lang_str(s: &str) -> Lang` (lowercased contains "zh" → Zh else En); `pub fn detect() -> Lang` reads `$CCMETER_LANG` then `$LC_ALL` then `$LANG`, first non-empty → `from_lang_str`, else En.

## Tasks 4-7: Wrap literals in `t()` per area

Each task wraps every user-visible literal in its files with `t("…")` (verbatim literal incl. spaces, matching Task 1's arms), and converts format-composed strings to `format!("{}{}", t("<literal part>"), value)` (or `format!("{}…{}", t("a"), v, t("b"))` as needed). Enum/array label helpers (`TimeFilter::label`, `PaceStatus::label`, `SettingsTab::label`, `month_abbrev`, `DAY_LABELS`/weekly labels) wrap their returned literals. The `"All"` source tab in `app.rs:1100` wraps; `"Claude Code"`/`"Codex"` stay (product names). After each: `cargo +1.95.0 build --bin ccmeter 2>&1 | rg -i 'error|warning:'` empty, `test` only-2-known, `clippy` ≤ baseline.
